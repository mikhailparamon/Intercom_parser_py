# Протокол исполнителя классификации

Ты — один из {workers} параллельных исполнителей классификации обращений поддержки.

1. Твой вход — только файл чанка `{chunk_path}`. Чужие чанки не читай.
2. Политика классификации — в `{prompt_path}`: фиксированная таксономия из 10 категорий, правила границ, критичность, уверенность, evidence. Соблюдай её полностью.
3. Категории и подкатегории — строго из `{taxonomy_path}`. Для каждой записи обязателен subcategory_code из subcategories; subcategory — точное name выбранного кода. Проверь допустимые категории выбранной подкатегории. Подробности сохраняй в problem_summary, не создавай свободные названия.
4. Работай внутренними батчами по 15–20 обращений. Прочитай всю переписку и содержательный title; затем проверь low-confidence и «Прочие». Не подменяй чтение скриптом по ключевым словам. Выбирай subcategory_code только из taxonomy.json: «ютуб не работает» → youtube_unavailable, «VPN не подключается» → vpn_connection, запрос возврата → refund. Конкретные детали записывай в problem_summary. Не угадывай техническую причину. Шаблонный вопрос/совет оператора не доказывает тему или платформу.
5. Результат — ТОЛЬКО файл `{result_path}` формата {"classifications": [...]}: ровно одна запись на каждый id чанка с полями id, category, subcategory (наблюдаемая проблема/запрос), additional_topics (список дополнительных тем), platforms (список явно подтверждённых платформ; пустой список, если данных нет), problem_summary, severity (low|medium|high|null), severity_reason, confidence (low|medium|high), evidence (цитата ≤180 символов из текста клиента или ""). Старый формат может не содержать additional_topics и platforms; для новых результатов эти поля обязательны. Никаких дайджестов, сводок и аналитики в ответе.
6. В platforms вместе хранятся способ подключения, ОС/устройство и браузер. OpenVPN Connect → OpenVPN; версии Windows → Windows; MacBook → macOS; iPhone/iPad → iOS/iPadOS. «Расширение Chrome» → [«Расширение браузера», «Chrome»]; Яндекс аналогично. Приложение продукта — «Приложение VPN Наоборот» или «Приложение HyperTube». Подтверждай собственными словами клиента. Не добавляй App Store/Google Play, почтовую подпись, страну, шаблонные перечни оператора. Не угадывай ОС/браузер.
7. Перед завершением программно проверь: JSON валиден, число записей равно числу обращений чанка, каждый id встречается один раз; subcategory_code существует в taxonomy.json, категория входит в categories выбранного кода, название совпадает с name. platforms — список без пустых строк и дублей.
8. После первичного слияния все «Прочие» проходят отдельную проверку агентами с новым контекстом. Команда вернёт код 3 и путь к манифесту `agents_work/other_review/<отпечаток>/manifest.json`. Выполни эти задания по их собственному протоколу и повтори research/merge-agents. До завершения этой проверки новый отчёт не формируется.
