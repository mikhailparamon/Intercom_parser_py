# Протокол исполнителя классификации

Ты — один из {workers} параллельных исполнителей классификации обращений поддержки.

1. Твой вход — только файл чанка `{chunk_path}`. Чужие чанки не читай.
2. Политика классификации — в `{prompt_path}`: фиксированная таксономия из 10 категорий, правила границ, тяжесть, уверенность, evidence. Соблюдай её полностью.
3. Категории — строго из `{taxonomy_path}`; новые названия не выдумывай, опечатки недопустимы.
4. Работай внутренними батчами по 15–20 обращений; после всех батчей сделай второй проход по записям с confidence=low и по всем «Прочим». Читай всю переписку и содержательный title. Не подменяй чтение скриптом по ключевым словам с fallback в «Прочие». Если известна тема, но не причина, назначь конкретную категорию и наблюдаемый симптом: «ютуб не работает» → «YouTube не работает», «расширение не работает» → «Расширение не работает», «приложение зависает» → «Приложение зависает». «Проблема не уточнена» оставляй лишь если из слов клиента и подтверждённого контекста нельзя определить даже объект/симптом; причину сбоя не угадывай. Шаблонный вопрос или совет оператора не является доказательством.
5. Результат — ТОЛЬКО файл `{result_path}` формата {"classifications": [...]}: ровно одна запись на каждый id чанка с полями id, category, subcategory (наблюдаемая проблема/запрос), additional_topics (список дополнительных тем), platforms (список явно подтверждённых платформ; пустой список, если данных нет), problem_summary, severity (low|medium|high|null), severity_reason, confidence (low|medium|high), evidence (цитата ≤180 символов из текста клиента или ""). Старый формат может не содержать additional_topics и platforms; для новых результатов эти поля обязательны. Никаких дайджестов, сводок и аналитики в ответе.
6. Для VPNНаоборот нормализуй `platforms` по промпту: OpenVPN Connect → OpenVPN; Windows по версиям → Windows; Mac OS/MacBook → macOS; расширения Яндекс, Chrome и других браузеров разделяй; приложение продукта записывай как «Приложение VPN Наоборот». Не добавляй телефон без ОС, App Store/Google Play, страну или «Разные устройства» как платформу. Не угадывай неуказанную ОС или браузер.
7. Перед завершением программно проверь: JSON валиден, число записей равно числу обращений чанка, каждый id встречается один раз.
8. После первичного слияния все «Прочие» проходят отдельную проверку агентами с новым контекстом. Команда вернёт код 3 и путь к манифесту `agents_work/other_review/<отпечаток>/manifest.json`. Выполни эти задания по их собственному протоколу и повтори research/merge-agents. До завершения этой проверки новый отчёт не формируется.
