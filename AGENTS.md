# AGENTS.md

Инструкции для AI-агентов, работающих с этим репозиторием.

## О проекте

CLI-приложение на Python для выгрузки обращений Intercom с историей переписки в форматированный JSON и подготовки отчёта по поддержке вручную через ChatGPT или оркестрацией субагентов.

- Язык интерфейса и документации: русский.
- Платформа разработки: Windows (Git Bash / PowerShell). Пути в командах — Windows-стиль.

## Стек

- Python 3.11+
- `requests` — HTTP к Intercom API
- `python-dotenv` — конфигурация через `.env`
- `tzdata` — часовые пояса
- `pytest` — тесты
- Виртуальное окружение: `.venv/` (использовать `.venv/Scripts/python.exe` на Windows)

## Структура

```
main.py                      # точка входа, вызывает cli.main()
src/intercom_exporter/
  cli.py                     # CLI-аргументы и оркестрация
  client.py                  # клиент Intercom API
  config.py                  # загрузка конфигурации из .env
  dates.py                   # работа с датами/периодами
  exporter.py                # выгрузка обращений в JSON
  monitoring.py              # мониторинг
  notify_slack.py            # отправка дашборда в Slack
  storage.py                 # сохранение результатов
  support_analysis.py        # отчёт по поддержке
  support_analysis_prompt_template.md  # шаблон промпта отчёта
tests/                       # тесты pytest (test_*.py, по модулю на файл)
data/                        # результаты выгрузки (в .gitignore, не коммитить)
docs/                        # документация
```

## Стандартный запуск (по умолчанию, без флагов)

Полный цикл исследования — строго две команды **без дополнительных флагов**: парсинг → очистка → пакет оркестрации → проверка оркестрации → слияние → отчёт → дашборд → отправка в Slack. Команды обрабатывают все настроенные сервисы (сейчас `vpn` — VPNНаоборот, и `hypertube` — HyperTube) подряд. Не добавляй `--standard`, `--start`/`--end`, `--full-archive`, `--workers`, `--skip-analysis`, `--no-agents`, `--service` и другие флаги, если пользователь явно не попросил.

### Первый запуск в новом окружении

1. Создай виртуальное окружение, если `.venv/` отсутствует (Python 3.11+): `python -m venv .venv`; на Windows дальше вызывай `.venv/Scripts/python.exe`.
2. Установи зависимости: `python -m pip install -r requirements.txt`.
3. Тестовый запуск без обращения к API: `python main.py --dry-run` (печатает интервалы, не читает токен) и `python -m pytest` (все тесты должны быть зелёными).
4. Убедись, что `.env` существует (шаблон — `.env.example`). Сам `.env` не читай.

### Полный цикл

1. `python main.py` — для каждого настроенного сервиса: выгрузка за скользящую неделю и день, очистка, пакет оркестрации субагентов (`agents_work/`). Данные каждого сервиса лежат в `data/<stamp>/<service>/`. Статус `partial` не останавливай: срезы строятся из выгруженного, детали в manifest.
2. `python analyze_support.py research` — проверка готовности воркеров по всем сервисам. Код возврата **3** означает «запусти субагентов»: подними по манифестам `agents_work/manifest.json` по одному субагенту на чанк (протокол — `agents_work/agents_protocol.md`) и повтори ту же команду. Если среда не умеет порождать субагентов — классифицируй чанки по очереди сам (см. «Оркестрация субагентов» ниже). Если у сервиса HyperTube ещё не утверждена таксономия, он пропускается на этом этапе.
3. Повторный `python analyze_support.py research` — проверка первичной разметки. Если есть «Прочие», команда готовит обязательные задания для их повторной проверки по полным очищенным перепискам и возвращает код **3** с путём к `agents_work/other_review/<отпечаток>/manifest.json`. Подними новых проверяющих по этому манифесту (с новым контекстом и собственным протоколом в каталоге проверки), затем повтори research. До готовности проверки всех сервисов не завершай цикл и не отправляй старые дашборды.
4. После готовности повторной проверки `research` выполняет слияние, валидацию и `report.md` по каждому сервису, общий `dashboard_DD_MM_YYYY.html` с вкладками «VPNНаоборот» / «HyperTube». Файл `other_review_audit.json` хранит решения по каждому проверенному ID и количества до/после. Если в `.env` заданы `SLACK_BOT_TOKEN` и `SLACK_CHANNEL_ID`, общий дашборд автоматически уходит в Slack одним сообщением (отключение `--no-notify` — только по просьбе пользователя).

После завершения сообщи пользователю: каталог прогона, число классификаций, пути к `report.md` и `dashboard_DD_MM_YYYY.html`, статус отправки в Slack.

## Команды

Все команды — из корня проекта, с активированным `.venv` (или явным `.venv/Scripts/python.exe`):

```bash
# Установка зависимостей
python -m pip install -r requirements.txt

# Запуск CLI
python main.py --help

# Все тесты
python -m pytest

# Один тестовый файл / один тест
python -m pytest tests/test_config_cli.py
python -m pytest tests/test_config_cli.py -k имя_теста
```

`pytest.ini` уже задаёт `pythonpath = src` — импорты вида `from intercom_exporter...` работают в тестах без установки пакета.

## Конфигурация и секреты

- Конфигурация — через `.env` (шаблон: `.env.example`). Переменные: `INTERCOM_ACCESS_TOKEN`, `HYPERTUBE_INTERCOM_ACCESS_TOKEN`, `INTERCOM_API_VERSION`, `AGENT_WORKERS`, `SLACK_BOT_TOKEN`, `SLACK_CHANNEL_ID`.
- **Никогда не читать и не выводить `.env`.** Только `.env.example`.
- `data/` содержит реальные выгрузки переписок — не коммитить, не отправлять наружу.

## Правила работы с кодом

- Поведенческие правила — в `CLAUDE.md` (принципы Karpathy: думай до кода, простота, хирургические правки, проверяемые цели). Соблюдай их.
- Минимальные точечные изменения: не рефактори соседний код, не меняй чужие комментарии, держи существующий стиль.
- Новая функциональность — с тестами в `tests/` по образцу существующих файлов.
- Перед завершением задачи прогони `python -m pytest` и убедись, что тесты зелёные.
- Не коммить без явной просьбы пользователя.

## Подкатегории и платформы

Подкатегория описывает проблему или запрос, а не платформу/устройство/тариф. `platforms` — отдельный список подтверждённых платформ, `additional_topics` — остальные темы обращения. Пустое/отсутствующее поле `platforms` в старом результате трактуется как пустой список. Дашборд ранжирует реальные подкатегории по частоте и показывает платформы отдельно. Политика и канонические примеры — в шаблонах промптов VPN и HyperTube.

## Оркестрация субагентов

- Число субагентов по умолчанию: переменная `AGENT_WORKERS` в `.env` (2–20; без неё — 10), переопределяется флагами `--agent-workers` (main.py) и `--workers` (prepare-monitoring, research).
- Если среда не умеет порождать субагентов, классифицируйте чанки по одному: прочитайте `agents_work/chunk_XX.json`, классифицируйте по `PROMPT.md`, запишите `agents_work/result_XX.json` (формат — `agents_work/agents_protocol.md`), забудьте контекст чанка и переходите к следующему; затем `merge-agents`. Не держите в контексте больше одного чанка.
