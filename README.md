# Intercom Conversation Exporter

CLI-приложение на Python для выгрузки обращений Intercom вместе с доступной историей переписки в JSONL. На этом этапе проект только выгружает данные: он не классифицирует обращения и не строит отчёты.

## Требования

- Python 3.11 или новее
- Git
- Intercom access token с разрешением на чтение обращений

## Установка (Windows PowerShell)

Из каталога проекта выполните:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если PowerShell запрещает активацию окружения, можно вызывать Python напрямую: `\.venv\Scripts\python.exe`.

В CMD активация выполняется так:

```cmd
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
copy .env.example .env
```

## Настройка Intercom

Создайте private app в Intercom Developer Hub и возьмите access token в Configure → Authentication. Для этого инструмента используйте токен только своего рабочего пространства; не публикуйте его и не передавайте третьим лицам. Подробности есть в [официальной документации Intercom по авторизации](https://developers.intercom.com/docs/build-an-integration/learn-more/authentication).

Откройте `.env` и заполните параметры:

```dotenv
INTERCOM_ACCESS_TOKEN=ваш_токен
INTERCOM_API_VERSION=2.17
```

Токен не принимается через CLI, не попадает в JSONL или manifest и не выводится в логах. `.env`, каталоги результатов, логи и виртуальное окружение исключены через `.gitignore`. Реальный токен в проекте не создавался.

## Использование

Запуск без параметров выгружает три предыдущих полных календарных месяца в UTC. Например, для запуска в октябре периодом будут 1 июля включительно — 1 октября исключительно.

```powershell
python main.py
```

Задать период явно:

```powershell
python main.py --start 2026-07-01 --end 2026-10-01
```

Проверить параметры без обращения к API:

```powershell
python main.py --start 2026-07-01 --end 2026-10-01 --dry-run
```

Сохранить результат в другой корневой каталог и включить подробные безопасные логи:

```powershell
python main.py --start 2026-07-01 --end 2026-10-01 --output exports --verbose
```

Параметры CLI:

| Параметр | Описание |
| --- | --- |
| `--start YYYY-MM-DD` | Начальная календарная дата UTC, включительно. Указывается вместе с `--end`. |
| `--end YYYY-MM-DD` | Конечная календарная дата UTC, исключительно. Указывается вместе с `--start`. |
| `--output PATH` | Корневой каталог результатов; по умолчанию `data`. |
| `--dry-run` | Печатает интервал и целевой каталог, не читает токен и не вызывает API. |
| `--verbose` | Подробное логирование без тел обращений и заголовков авторизации. |

Дата окончания должна быть позже даты начала. Для дат `[2026-07-01, 2026-10-01)` запрос включает обращения с `created_at` начиная с полуночи 1 июля до полуночи 1 октября UTC.

## Правило отбора и история

Критерий отбора — только время создания обращения (`created_at`). Даты последнего обновления, закрытия, сообщений и текущий статус не влияют на включение. Например, обращение, созданное до начала периода, исключается даже при обновлении внутри периода; обращение, созданное в период и закрытое позже, включается.

Фильтр периода не применяется к отдельным сообщениям: у выбранного обращения сохраняются все возвращённые API части переписки, в том числе созданные до начала или после конца периода.

Приложение использует документированный `POST /conversations/search` с фильтром по `created_at`, проходит cursor pagination и локально повторно проверяет границы периода. Детали получает через `GET /conversations/{id}`. Используемая версия API задаётся заголовком `Intercom-Version`.

### Ограничение Intercom

Документация Intercom указывает жёсткий предел в 500 частей переписки на один retrieve: API возвращает до 500 наиболее новых частей. Список обращений содержит счётчик частей, поэтому если он больше реально полученного количества, manifest отмечает выгрузку как `partial` и указывает известное ограничение. Это ограничение относится к API и не может быть устранено клиентской пагинацией. См. [поиск обращений](https://developers.intercom.com/docs/references/rest-api/api.intercom.io/conversations/searchconversations) и [получение обращения с частями переписки](https://developers.intercom.com/docs/references/rest-api/api.intercom.io/conversations/retrieveconversation).

## Файлы результата

По умолчанию результаты записываются в `data/<start>_<end>/`:

- `conversations.jsonl` — UTF-8, одно обращение на строку, включая доступные части переписки и основные метаданные;
- `manifest.json` — период, время запуска, версия API, найденные/экспортированные обращения, число ошибок, статус и известные ограничения.

Сохраняются ID и даты обращения, заголовок, состояние, назначенные оператор/команда, теги, доступные пользовательские атрибуты, контактные ID, сведения об источнике и частях переписки. Email контактов и авторов не включаются. Для сообщений сохраняются автор (ID, тип, имя), время, тип, текст и метаданные вложений; содержимое вложений не скачивается. Если Intercom не вернул поле, оно не подменяется вымышленным значением.

Повторный запуск для того же периода безопасно объединяет данные по ID обращения: обновлённые записи заменяют старые, дубликаты удаляются. Новый файл записывается во временный файл и атомарно заменяет прежний после успешной сборки результата.

`status` manifest будет `success`, если не было ошибок или обнаруженного усечения истории, и `partial`, если API-запросы завершились ошибкой или выявлено ограничение частей переписки. При сбое выгрузка не считается полной.

## Ошибки и повторные запросы

- Ошибки авторизации HTTP 401/403 не повторяются.
- HTTP 429 и временные HTTP 5xx повторяются ограниченное число раз с экспоненциальной задержкой; учитывается `Retry-After`.
- Сетевые ошибки и тайм-ауты повторяются ограниченное число раз.
- Цикл курсорной пагинации обнаруживается и завершает обработку с ошибкой.
- В логах нет текстов переписок, токена или заголовков запроса.
- Для частичного результата manifest содержит статус `partial` и число ошибок.

## Тесты

Тесты используют фиктивные HTTP-ответы и не подключаются к Intercom:

```powershell
python -m pytest -q
```

## Частые проблемы

- **Не задан `INTERCOM_ACCESS_TOKEN`** — проверьте `.env`; `.env.example` является только шаблоном.
- **HTTP 401/403** — проверьте токен, workspace приложения и доступ к чтению разговоров.
- **HTTP 429 или временная ошибка сервера** — клиент автоматически выполнит ограниченные повторы; при исчерпании повторов экспорт будет отмечен как частичный.
- **`partial` при большом разговоре** — retrieve Intercom ограничен 500 самыми новыми частями.
- **Неверные даты** — задавайте обе даты в `YYYY-MM-DD`; конец должен быть позже начала.

## Конфиденциальность

Экспорт содержит клиентские сообщения и чувствительные данные. Храните каталог результатов с соответствующими ограничениями доступа, не добавляйте его в Git и удаляйте по политике хранения вашей организации. Утилита не выполняет реальных запросов, пока пользователь не укажет токен в `.env` и сам не запустит обычный режим CLI.
