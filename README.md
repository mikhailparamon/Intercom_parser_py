# Intercom Conversation Exporter

CLI-приложение на Python для выгрузки обращений Intercom вместе с доступной историей переписки в форматированный JSON и отдельной подготовки отчёта по поддержке с ручным анализом через ChatGPT.

## Требования

- Python 3.11 или новее
- Git
- Intercom access token с разрешением на чтение обращений

## Установка (Windows PowerShell)

Из каталога проекта выполните:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Если PowerShell запрещает активацию окружения, можно вызывать Python напрямую: `\.venv\Scripts\python.exe`.

В CMD активация выполняется так:

```cmd
.venv\Scripts\activate.bat
python -m pip install -r requirements.txt
copy .env.example .env
```

## Установка (Linux)

Нужен Python 3.11 или новее и Git. Для Debian/Ubuntu установите системные пакеты:

```bash
sudo apt update
sudo apt install -y git python3 python3-venv python3-pip
python3 --version
```

Если `python3 --version` показывает версию ниже 3.11, установите Python 3.11+ средствами своего дистрибутива и далее указывайте соответствующую команду, например `python3.11`.

Перейдите в каталог проекта, создайте виртуальное окружение и установите зависимости:

```bash
cd intercom-conversation-exporter
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
cp .env.example .env
```

Команды активации подходят для Bash и Zsh. Чтобы выйти из окружения, выполните `deactivate`.

Проверьте, что установлен Python 3.11+ и Git. Если их нет, установите Homebrew с [официального сайта](https://brew.sh/), затем выполните:

brew install python@3.11 git

Сначала клонируйте репозиторий по его URL или распакуйте архив проекта. Команды ниже выполняйте из корневого каталога `intercom-conversation-exporter`.

Создайте виртуальное окружение, установите зависимости и скопируйте шаблон настроек:

```bash

source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt

```

Для выхода из виртуального окружения выполните `deactivate`.

## Настройка `.env` на Linux и macOS

Заполните `.env` по разделу «Настройка Intercom» ниже. Перед реальной выгрузкой проверьте параметры без обращения к API:

```bash
python main.py --dry-run
```

## Настройка Intercom

Создайте private app в Intercom Developer Hub и возьмите access token в Configure → Authentication. Для этого инструмента используйте токен только своего рабочего пространства; не публикуйте его и не передавайте третьим лицам. Подробности есть в [официальной документации Intercom по авторизации](https://developers.intercom.com/docs/build-an-integration/learn-more/authentication).

Откройте `.env` и заполните параметры:

```dotenv
INTERCOM_ACCESS_TOKEN=ваш_токен
INTERCOM_API_VERSION=2.17
```

Токен не принимается через CLI, не попадает в экспорт или manifest и не выводится в логах. `.env`, каталоги результатов, логи и виртуальное окружение исключены через `.gitignore`. Реальный токен в проекте не создавался.

## Использование

Запуск без параметров включает режим мониторинга. Он выгружает полный набор полей Intercom для обращений с активностью за последние три завершённых календарных месяца UTC, сохраняет его как архив и выделяет из него данные за последние семь завершённых дней и за вчера. Например, при запуске 31 октября 2026 года архив охватывает `[2026-07-31, 2026-10-31)`, неделя — `[2026-10-24, 2026-10-31)`, день — `[2026-10-30, 2026-10-31)`. Начало трёхмесячного периода ограничивается последним днём целевого месяца, если исходный день там отсутствует.

```powershell
python main.py
```

Проверить мониторинговые интервалы без обращения к API:

```powershell
python main.py --dry-run
```

Прежний режим экспорта с произвольным периодом запускается через `--standard`:

```powershell
python main.py --standard --start 2026-07-01 --end 2026-10-01
```

Проверить обычный экспорт без обращения к API:

```powershell
python main.py --standard --start 2026-07-01 --end 2026-10-01 --dry-run
```

По умолчанию детали обращений запрашиваются в 15 потоков. При необходимости параллелизм можно изменить, например `--workers 6`; слишком большое значение может привести к ответам API `429` и задержкам на повторных запросах.

Параметры CLI:

| Параметр | Описание |
| --- | --- |
| `--standard` | Запустить прежний экспорт вместо мониторинга. Только в этом режиме доступны `--start`, `--end`, `--selection` и `--fields`. |
| `--start YYYY-MM-DD` | Начальная календарная дата UTC, включительно; используется вместе с `--standard` и `--end`. |
| `--end YYYY-MM-DD` | Конечная календарная дата UTC, исключительно; используется вместе с `--standard` и `--start`. |
| `--output PATH` | Корневой каталог результатов; по умолчанию `data`. |
| `--workers N` | Максимальное количество одновременных запросов деталей; по умолчанию `15`, должно быть не меньше `1`. |
| `--selection {new,updated,all}` | Тип обращений в обычном режиме; по умолчанию `all`. Мониторинг всегда использует `all`. |
| `--fields {important,all}` | Набор полей в обычном режиме; по умолчанию `important`. Мониторинг всегда использует `all`. |
| `--timezone TIMEZONE` | Формат временных полей: `UTC` (по умолчанию), имя IANA, например `Europe/Moscow`, или `unix` для исходных Unix-значений. |
| `--dry-run` | Печатает мониторинговые интервалы или период обычного экспорта, не читает токен и не вызывает API. |
| `--skip-analysis` | Не запускает автоматическую подготовку файлов для ChatGPT после успешного экспорта. |
| `--verbose` | Подробное логирование без тел обращений и заголовков авторизации. |

Мониторинг выполняет один запрос полного набора за три месяца с `selection=all` и `fields=all`, затем формирует локальные срезы по `created_at`, `updated_at` или времени любой части переписки. Текущий незавершённый день исключён. Результаты находятся в уникальной папке запуска: `backup_3_months/`, `last_week/` и `last_day/`; в каждой лежат `conversations.json` и `manifest.json`.

Для ChatGPT создаётся одна папка `support-analysis/` с `chatgpt_input_week.json`, `chatgpt_input_day.json` и одним `PROMPT.md`. Промпт требует классифицировать общий набор уникальных ID один раз, а выводы подготовить для каждого окна отдельно. Дневной набор входит в недельный, поэтому их частоты нельзя складывать. Если один срез пуст, его JSON всё равно создаётся, когда другой срез содержит обращения. `--skip-analysis` отключает подготовку, но не создание срезов.

При частичном экспорте доступные обращения сохраняются и используются для срезов; статус `partial` и ошибки исходного экспорта отражаются в манифестах. В обычном режиме `--standard` автоматически подготавливается анализ полной выгрузки, как и раньше.

Дата окончания должна быть позже даты начала. Для дат `[2026-07-01, 2026-10-01)` период включает события начиная с полуночи 1 июля и до полуночи 1 октября UTC.

## Правило отбора и история

`--selection` определяет, какие обращения попадут в выгрузку:

- `new` — обращения, созданные внутри выбранного периода;
- `updated` — обращения, созданные до начала периода и обновлённые внутри него по `updated_at` или времени любой части переписки;
- `all` — объединение новых и обновлённых старых обращений.

Для дат `[2026-07-01, 2026-10-01)` начало включается, конец исключается; все временные границы рассчитываются в UTC. Сообщения, системные события, назначения, закрытия и повторные открытия частей считаются активностью.

После включения обращения сохраняются все доступные части его истории, в том числе созданные до начала и после конца периода. Сам период определяет отбор обращения, а не обрезает его историю.

Приложение использует `POST /conversations/search` с пагинацией и фильтрами-кандидатами по `created_at` и `updated_at`, затем локально проверяет время создания, обновления и частей переписки. Чтобы найти старое обращение, которое продолжили в периоде, поиск может вернуть также обращения, обновлённые после конца периода; окончательное решение принимается по точным временным границам. Детали получает через `GET /conversations/{id}`. Версия API передаётся в заголовке `Intercom-Version`.

### Ограничение Intercom

Документация Intercom указывает жёсткий предел в 500 частей переписки на один retrieve: API возвращает до 500 наиболее новых частей. Счётчик частей используется для обнаружения усечения. Если период активности невозможно проверить по усечённой истории, manifest отмечает выгрузку как `partial`; часть продолжений может быть не обнаружена. Этот предел нельзя обойти клиентской пагинацией. См. [поиск обращений](https://developers.intercom.com/docs/references/rest-api/api.intercom.io/conversations/searchconversations), [схему части переписки](https://developers.intercom.com/docs/references/rest-api/api.intercom.io/models/conversation_part) и [получение обращения](https://developers.intercom.com/docs/references/rest-api/api.intercom.io/conversations/retrieveconversation).

## Файлы результата

Мониторинг сохраняет запуск в `data/<start>_<end>_run_<UTC-время>/`; повторные запуски не перезаписывают предыдущие. В обычном режиме результаты находятся в `data/<start>_<end>/`, а повторный запуск получает уникальный суффикс.

- `conversations.json` — UTF-8, форматированный JSON-массив обращений;
- `manifest.json` — период, время запуска, выбранные `selection` и `fields`, длительность экспорта в секундах (`elapsed_seconds`), версия API, число обращений, ошибок, статус и известные ограничения. В мониторинге эти файлы лежат в каждой из трёх папок-срезов; манифест архива также сохраняет метаданные исходного экспорта.

По умолчанию `--fields important` сохраняет `id`, `title`, `created_at`, `updated_at`, текст начального сообщения (`source.body`) и текст частей переписки. Для каждой части остаются `part_type`, `created_at` и тип автора, чтобы различать сообщения клиента, ответы оператора и системные события. Контакты, идентификаторы авторов, вложения и остальные служебные поля исключены. `--fields all` сохраняет весь объект, который вернул Intercom для обращения, вместе со всеми вложенными полями и исходной структурой API.

После завершения CLI и в логе показывается длительность в формате `часы минуты секунды`, например `0 ч 0 мин 5 сек`. Секунды округляются до ближайшего целого. Длительность измеряется монотонными часами от начала выгрузки до сохранения JSON.

При `--fields all` сохраняются все поля, фактически возвращённые API, включая email и другие персональные данные, если они есть в ответе. Структура `conversation_parts` сохраняется без преобразований. Этот режим может содержать конфиденциальную информацию.

Временные поля в обоих режимах по умолчанию преобразуются в ISO 8601 UTC с суффиксом `Z`, например `"created_at":"2026-10-27T11:56:00Z"`. Укажите IANA-зону, чтобы получить её местное время с UTC-смещением; преобразование учитывает сезонные переходы. `--timezone unix` оставляет временные поля числами, как их вернул Intercom. Выбранный режим записывается в `manifest.json`; время запуска `started_at` всегда сохраняется с UTC-смещением.

Примеры выбора часового пояса в обычном режиме:

```powershell
python main.py --standard --start 2026-07-01 --end 2026-10-01 --timezone Europe/Moscow
python main.py --standard --start 2026-07-01 --end 2026-10-01 --fields all --timezone unix
```

Каждый запуск записывается в собственную папку. До полной сборки JSON во временном файле результат текущего запуска не появляется; прежние каталоги и файлы остаются без изменений.

`status` manifest будет `success`, если не было ошибок или обнаруженного усечения истории, и `partial`, если API-запросы завершились ошибкой или выявлено ограничение частей переписки. При сбое выгрузка не считается полной.

## Анализ обращений через ChatGPT

Анализ работает локально в два этапа и не использует OpenAI API или API-ключ. Сначала подготовьте файлы для ChatGPT:

```powershell
python analyze_support.py prepare --input data/2026-10-27_2026-10-30/conversations.json
```

В обычном режиме `--standard` рядом с выгрузкой появятся `support-analysis/chatgpt_input.json` и инструкция `support-analysis/PROMPT.md`.

В режиме мониторинга загрузите в ChatGPT Work оба файла `support-analysis/chatgpt_input_week.json`, `support-analysis/chatgpt_input_day.json` и общий `support-analysis/PROMPT.md`. Сохраните единый результат ChatGPT как `support-analysis/chatgpt_result.json`. Он должен содержать по одной классификации на уникальный ID и отдельные сводки для недели и дня.

Проверить результат и локально создать единые `report.md` и `classifications.csv` можно командой:

```powershell
$runDir = "data\2026-07-31_2026-10-31_run_<UTC-время-запуска>"
python analyze_support.py report-monitoring --week "$runDir\last_week\conversations.json" --day "$runDir\last_day\conversations.json" --result "$runDir\support-analysis\chatgpt_result.json"
```

Команда проверит полноту объединения, fingerprints обоих окон и членство ID, затем создаст один отчёт с отдельными рейтингами для недели и дня и сравнительной таблицей. Совпадающие ID классифицируются один раз; в CSV указывается, к каким окнам относится каждое обращение. Для повторной подготовки пары входов без нового экспорта используйте `analyze_support.py prepare-monitoring --week ... --day ... --output ...`.

Анализатор читает новый формат `conversations.json` и поддерживает старые выгрузки `conversations.jsonl`.

Один запрос не гарантирует, что ChatGPT завершит классификацию любого набора вплоть до 10 000 записей: это зависит от размера и сложности текстов, доступных инструментов и лимитов текущего режима. Поэтому инструкция требует не заявлять о завершении при пропусках и записывать `complete: false`; локальная проверка дополнительно сверяет число обращений, все ID и fingerprint исходного набора. Неполный результат отчёт не создаст.

Сохраните скачанный JSON как `support-analysis/chatgpt_result.json`. При желании проверьте и пересоздайте `report.md` и `classifications.csv` локально по валидированной классификации:

```powershell
python analyze_support.py report --input data/2026-10-27_2026-10-30/conversations.json --result data/2026-10-27_2026-10-30/support-analysis/chatgpt_result.json
```

Команда создаст `report.md` для руководителя и `classifications.csv` с классификацией каждого обращения. Частоту по категориям и распределение тяжести считает программа по уникальным ID, а не берёт из текстовых оценок ChatGPT. Если классификация неполная, содержит неизвестные или дублированные ID либо категории/уровни тяжести не соответствуют схеме, отчёт не создаётся.

Перед подготовкой скрипт удаляет из заголовков и текста найденные email, телефонные номера, секреты по распространённым шаблонам, URL и типовые подписи. Остальной текст и исходные ID сохраняются. Это очистка по правилам, она не гарантирует обнаружение каждого секрета или персональных данных; имена остаются. Просмотрите `chatgpt_input.json` перед загрузкой в ChatGPT. Файлы подготовки и результата содержат текст обращений и исключены из Git, если находятся внутри `data/`.

## Ошибки и повторные запросы

- Ошибки авторизации HTTP 401/403 не повторяются.
- HTTP 429 и временные HTTP 5xx повторяются ограниченное число раз с экспоненциальной задержкой; учитывается `Retry-After`.
- Сетевые ошибки и тайм-ауты повторяются ограниченное число раз.
- Цикл курсорной пагинации обнаруживается и завершает обработку с ошибкой.
- В логах нет текстов переписок, токена или заголовков запроса.
- Для частичного результата manifest содержит статус `partial` и число ошибок.

## Частые проблемы

- **Не задан `INTERCOM_ACCESS_TOKEN`** — проверьте `.env`; `.env.example` является только шаблоном.
- **HTTP 401/403** — проверьте токен, workspace приложения и доступ к чтению разговоров.
- **HTTP 429 или временная ошибка сервера** — клиент автоматически выполнит ограниченные повторы; при исчерпании повторов экспорт будет отмечен как частичный.
- **`partial` при большом разговоре** — retrieve Intercom ограничен 500 самыми новыми частями.
- **Неверные даты** — задавайте обе даты в `YYYY-MM-DD`; конец должен быть позже начала.

## Конфиденциальность

Экспорт содержит клиентские сообщения и чувствительные данные. Храните каталог результатов с соответствующими ограничениями доступа, не добавляйте его в Git и удаляйте по политике хранения вашей организации. Утилита не выполняет реальных запросов, пока пользователь не укажет токен в `.env` и сам не запустит обычный режим CLI.
