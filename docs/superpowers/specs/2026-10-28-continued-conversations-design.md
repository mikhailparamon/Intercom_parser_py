# Отбор продолженных обращений — дизайн

## Цель

Включать в экспорт обращения, созданные в периоде, обновлённые в периоде или имеющие часть переписки, созданную в периоде.

## Семантика дат

Период остаётся полуоткрытым UTC интервалом `[start, end)`. Отбор выполняется по объединению условий:

1. `conversation.created_at` попадает в интервал;
2. `conversation.updated_at` попадает в интервал;
3. `conversation_parts[].created_at` попадает в интервал.

Любой тип части переписки считается активностью, включая сообщение, назначение, закрытие, повторное открытие и системное событие. Если обращение прошло отбор, JSONL содержит всю доступную историю; сообщения не обрезаются по датам.

## Получение кандидатов

Intercom Search поддерживает поля `created_at` и `updated_at`, но не фильтрует результаты по времени создания каждой conversation part. Поэтому API возвращает кандидатов по условию: обращение создано в выбранном интервале ИЛИ создано до его конца и обновлено начиная с начала периода. После retrieve приложение проверяет точные временные границы локально.

## Ограничение полноты

Retrieve возвращает максимум 500 последних conversation parts. Если счётчик Intercom показывает больше элементов, чем доступно в ответе, обращение или возможное совпадение нельзя проверить полностью. Manifest должен отметить такой результат как `partial` и описать потенциально пропущенную активность.

## Проверка

Тесты покрывают включение по created_at, updated_at и любому part.created_at; исключение записей вне периода; границы UTC; сохранение полной истории; повторную пагинацию и признак partial при усечённой истории.
