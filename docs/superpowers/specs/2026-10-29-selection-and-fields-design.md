# Выбор обращений и компактная выгрузка — дизайн

## Цель

Добавить явный выбор типа обращений и объёма сохраняемых полей, чтобы экспортировать новые обращения, продолжения старых или оба вида, а для аналитики поддержки получать компактный файл без лишних персональных и служебных полей.

## Параметры CLI

- `--selection {new,updated,all}` выбирает новые, обновлённые старые или все обращения. Значение по умолчанию — `all`.
- `--fields {important,all}` выбирает компактный или полный набор данных. Значение по умолчанию — `important`.
- `--dry-run` показывает выбранный период, тип отбора и объём полей без API-запросов.

## Семантика отбора

Период — полуоткрытый UTC интервал `[start, end)`.

- `new`: обращение создано внутри периода (`created_at`).
- `updated`: обращение создано до начала периода и имеет `updated_at` либо `conversation_parts[].created_at` внутри периода.
- `all`: объединение `new` и `updated`. Обращение, созданное в периоде, относится к `new`, даже если оно также обновлялось в этом периоде.

Все части переписки считаются активностью, включая назначения, закрытия, повторные открытия и системные события. После отбора сохраняется вся доступная история. При усечении истории на лимите Intercom неопределённость по-прежнему отражается в manifest как `partial`.

## Форматы данных

`important` сохраняет поля обращения `id`, `title`, `created_at`, `updated_at`, текст начального сообщения и текст истории. Для каждой реплики истории сохраняются `part_type`, `created_at`, тип автора и `body`, если эти значения присутствуют. Это сохраняет различие между клиентскими сообщениями, ответами операторов и системными событиями.

`all` сохраняет нынешний набор нормализованных полей без изменений.

Фильтрация `important` ограничивает сохраняемый JSONL, но не меняет запрос retrieve к Intercom: API всё равно используется для точного отбора по истории и получает те же детали.

Manifest указывает выбранные `selection` и `fields` вместе с существующими счётчиками и статусом.

## Проверка

Тесты покрывают каждый режим отбора, границы периода, сохранение компактного набора и неизменность полного набора. CLI-тесты покрывают значения по умолчанию, переданные параметры и dry-run; README описывает параметры и компактную структуру.
